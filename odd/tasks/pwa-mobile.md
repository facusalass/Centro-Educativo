# Feature: pwa-mobile

## Objective
Implement Part 3 of the TPI for Centro Educativo "Educar para Transformar" on integration branch `feat/pwa-mobile` (branched from `main` @ `55f3ebe`): an installable Progressive Web App (PWA) for `padre` and `alumno` roles, differentiated service pricing (`deportes.arancel_mensual`, `recorridos_transporte.arancel_mensual`), monthly itemized invoicing (`facturas`, `factura_items`), bank transfer proof uploads and admin validation with automatic receipt generation (`pagos_comprobantes`, `pago_comprobante_items`, `recibos`), automated email jobs (last business day of the month with invoice attachment, and 20th-of-month overdue debt notice), and the 5 web financial/payment reports (`RF-06.1`–`RF-06.5`).

## Problem & Why
The existing system on `main` (`55f3ebe`) provides complete academic, attendance, evaluation, and service enrollment management (`deporte`, `transporte`, `comedor`), plus flat-rate fee quotes (`server/core/fees.ts`), JWT/BCrypt RBAC (`server/core/security.ts`), and an SMTP notification outbox (`server/core/notifications.ts`). However, it lacks differentiated pricing per sport and transport route, monthly invoice generation, bank transfer proof submission and validation, receipt issuance, itemized debt tracking, scheduled billing emails, installable PWA assets, self-service password recovery, and the 5 financial reports required by Part 3 (`docs/tpi_scenario_mobileApp.md` & `docs/PLAN_DE_TRABAJO_PWA.md`).

## Verified Baseline Architecture (`main` @ `55f3ebe`)
- **Frontend:** React 19 + TypeScript + Vite 7 SPA (`src/App.tsx`, `src/pages/LoginPage.tsx`, `src/pages/PortalPage.tsx`, `src/pages/ManagementPage.tsx`, `src/components/ReportesViewer.tsx`, `src/services/http.ts`). Note: `alumno` can already log in and view `src/components/portal/StudentProfile.tsx`, `src/components/portal/PasswordForm.tsx`, `src/components/AcademicPanel.tsx`, and `src/components/Notifications.tsx` (the last two live at `src/components/` root, not under `portal/`) inside `src/pages/PortalPage.tsx`.
- **Backend:** Node.js 22 + Express 5 (`server/index.js`, `api/index.js`, `server/core/routes.ts`).
- **Database:** Dual PostgreSQL (`pg`) / SQLite (`node:sqlite`) wrapper in `server/database.js` (`query`, `run`, `get`, `transaction` — there is no `withTransaction` export), schema in `server/data/schema.js`, incremental migrations gated on `MAX(version)` in `server/database.js:259` (v1 in `server/core/migrations.ts`; v2–v4 in `server/core/constraints.ts` — latest is **v4**, so the financial schema extension is **Migration v5**), and demo seed in `server/data/demo-seed.js`.
- **Auth & RBAC:** Custom JWT (`HS256` in `educar_session` cookie or `Authorization: Bearer`) + `bcryptjs` (cost 12) in `server/core/security.ts`. Change-password (`PUT /api/auth/password`) is already built; forgot/reset password via email token is not yet built.
- **Notifications:** Persistent `notificaciones` table + `nodemailer` SMTP worker in `server/core/notifications.ts`. Caveat: the worker sends `text`-only mail today — no `attachments` support (needed by T04).
- **Reports:** The 9 existing `/api/reportes/*` GET endpoints live in `server/routes/reports.js` (registered from `server/index.js:72`, NOT `server/core/routes.ts`) and are currently **unauthenticated** — the 5 new financial reports must NOT copy that legacy pattern and require `admin` session middleware. Frontend CSV export and `window.print()` already exist in `src/components/ReportesViewer.tsx` / `src/components/reports/renderers.tsx`. There is no binary upload handling anywhere in `server/` today (T03 is greenfield: no `multer`/`multipart` dependency exists).

## Acceptance Criteria & Applicable Checks
- All 26 user stories (`HU-01`–`HU-26`) in `docs/PLAN_DE_TRABAJO_PWA.md` implemented on `feat/pwa-mobile`.
- Differentiated rates per sport and transport route persist and feed `monthlyQuote` and `generateMonthlyInvoices`.
- `padre` can only access their own linked children (`403` on other students); `alumno` has read-only access to their own enrollments and cannot access payment/invoice endpoints (`403`).
- Bank transfer proof upload validates `JPG/PNG/PDF <= 5MB`, supports multiple proofs per invoice, transitions selected items to `en_revision`, and only credits balances / emits a `recibo` when approved by `admin` inside an ACID transaction. Proof files are retrievable only by `admin` or the owning `padre` via `GET /api/comprobantes/:id/archivo` (`403` otherwise). The displayed `vencida` status is derived at read time (D2) and never persisted.
- Max 2 active `deporte` enrollments per student, enforced at enrollment time (D3); monthly invoicing inherits the cap.
- End-of-month and 20th-of-month email jobs record executions in `avisos_facturacion_log` and do not duplicate sends for the same `(periodo, tipo_aviso, factura_id)`.
- All 5 web financial reports render in `ReportesViewer.tsx` with CSV and print/PDF support.
- `npm test` and `npm run build` pass with 0 errors after each task.
